- On a disk that folds names, a path that named a nested mount's directory, or a directory above it, in a spelling other than the ones read at start was the outer mount's own. A draft could be written there, a file read and listed, and a materialize wrote into the nested mount's directory, a read-only mount's included. That held with nothing there on disk, with the directory or its parent made or renamed after start, with history spelling a parent otherwise, with a name typed with `ß` where the directory is `ss` on a disk that folds them together, with a soft hyphen or a zero-width joiner inside the name on a disk that passes over them, as Linux's casefold does, and through a link whose target spells the directory otherwise. Every check now compares a path with a nested mount's directory as disk compares names, level by level: in either Unicode normalization form at every level, and at a level whose directory folds case, in any case and with default-ignorable code points passed over, as Linux's casefold compares names, each level's folding read at each start: from that directory's own entries within a mount's root, and from the path's own name there above every root. Such a path is refused, naming the nested mount and the path to use there, and walks and pushes pass over it. Where the comparison can't tell the path's spelling from the directory's, which only a disk that tells names apart can hold as two names, the refusal says the path may lie in the nested mount, shows both spellings, and gives a step for each thing the caller may have meant; where a followed link leads outside the mount, it says only that it can't tell.

Through a link into a nested mount's directory, the place beneath it is judged by that mount's include, and named, as disk spells it, where it was judged in the link's spelling.
