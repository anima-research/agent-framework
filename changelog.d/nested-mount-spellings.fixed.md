- On a disk that folds names, a path that named a nested mount's directory, or a directory above it, in a spelling other than the ones read at start was the outer mount's own. A draft could be written there, a file read and listed, and a materialize wrote into the nested mount's directory, a read-only mount's included. That held with nothing there on disk, with the directory or its parent made or renamed after start, with history spelling a parent otherwise, with a name typed with `ß` where the directory is `ss` on a disk that folds them together, with a soft hyphen or a zero-width joiner inside the name on a disk that passes over them, as Linux's casefold does, and through a link whose target spells the directory otherwise. Every check, `resolveAbsolutePath`'s included, now compares a path with a nested mount's directory as any disk may compare names, level by level: in either Unicode normalization form and in any case, as fully as a disk that folds names may compare them, with default-ignorable code points passed over, at every level, reading nothing from the disk to do so. Such a path is refused, naming the nested mount and the path to use there, and walks and pushes pass over it. Where the path matches the directory only that loosely, not exactly, or lies beneath a nested mount that start placed only by such a match of the real roots, however exactly it matches there, the refusal says the path may lie in the nested mount, shows both spellings, and gives a step for each thing the caller may have meant; where a followed link leads outside the mount, it says only that it can't tell.
- On such a disk, a mount configured through a link, or in a spelling, other than disk's wasn't always found nested, and the outer mount held its files as its own. Start now places each mount by the same comparison. Through a link into a nested mount's directory, the place beneath it is judged by that mount's include, and named, as disk spells it, where it was judged in the link's spelling.
- The cases that fall outside the nested-mount guarantee, which 0.24.0's entry for `include` listed as four, are now these: on a disk whose folding goes past the comparison's, a name the comparison keeps apart can reach the directory; a second path to the directory that isn't a link, such as a bind mount, isn't found to lead there, though a walk passes over it; a nested mount whose root moves while running, as `acceptRoot` takes, stays placed where it was until the next start, but for the calls of a direct mount whose root has moved and on or beneath whose path it's configured, which place it where it lies; and on a direct mount, a root repointed between a read's parse and its open, or a write's parse and its staging, can have the read serve a path in a mount nested in it by its directories alone, or the write land there.
