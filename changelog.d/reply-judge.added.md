- A new wake-rule behavior, `judge`, that asks a small model before waking the agent. A judge rule batches matching events as a debounce does (`debounceMs`, with an optional `maxWaitMs` that judges a batch by then even while messages keep coming). When the batch fires, the reply judge reads three things: the agent's context as one document (the request the agent would send if woken now, `previewActivation`'s dry run, newest part first, cut to fit), the agent's own `instructions` to it, and the batch. It answers `REPLY` or `WAIT`. On reply the batch wakes the agent as a debounce's would. On wait it doesn't, and the events stay in context, as for `defer`. A batch holding an event addressed to the agent (`chat:addressed`: a mention, a reply or a DM) wakes it without asking the judge.
- Batches are judged against the context as it stands after the residents' turns, since the residents share the message slot the judge reads. A batch that fires while a resident's turn runs or the host is quiesced is held, then judged once both are clear. A resident's turn that starts while the judge decides, or a quiesce, stops the judge, and its batch is judged once the turn ends or at resume, so a turn that already answered the messages isn't followed by a second wake for them, and the turn never waits for the judge. A stopped call is no verdict: it wakes nothing and isn't counted as a failure. A fork's or the subconscious's turn, in a store of its own, neither holds a judge rule's batch nor stops the judge. A judge rule's batch that is waiting, held or being judged when the rule is removed is still judged, by the rule as it was, and `wake_remove_rule` says so where a judge is wired. What a rule holds for the judge is capped at the inference buffer's 100 events, dropping the oldest, which `inferenceDiagnostics()` counts.
- Where the host wires a judge, the agent writes judge rules with `wake_add_rule`'s new `judge` parameter. Elsewhere the tool is as it was. gate_status shows each judge rule's verdict counts and its newest verdict, with the judge's reason. It also says when a judge rule is in force with no judge wired, and when the judge has failed three times in a row. Each verdict is traced as `gate:judge-verdict`, with its counts and tokens but not the judge's reason, which is written from the agent's context.
- The judge is `ReplyJudge` (`src/gate/reply-judge.ts`), wired only when the host sets `GateOptions.judge`, which configures it. The package root exports it with the judge's types, `JudgeEventSummary` among them:
  - `model`: default `claude-haiku-5-5`.
  - `maxInputTokens`: default 90,000, under the 100K line past which Haiku 5.5 costs five times as much; at least 8,000 (a smaller value is read as 8,000, with a log line).
  - `timeoutMs`: default 20,000.
  - `onError`: `"wake"` (the default) or `"skip"`.
  - `effort`: default `"low"`; `"none"` sends none, for a provider without Anthropic's `output_config`.
  - `cacheTtl`: `"5m"` (the default) or `"1h"`.
  - `enabled: false` leaves it unwired.
- How the judge calls its model:
  - A model its provider holds is refused, and a call is withdrawn under a surgery or a stop, as for compression. It takes no provider admission, so none of the agent's turns waits for it.
  - Each request's usage counts as the judged agent's, in its usage tally and the session's totals, as a turn's does.
  - It always uses membrane's native formatter: an XML-formatted request would end in a prefill, which current Claude models refuse.
  - Input tokens are estimated at a ratio corrected from every response's reported usage.
  - The document goes in chunks from a fixed first message, with a cache breakpoint after the last full chunk, so successive requests read most of it from the prompt cache.
  - The batch's listing is capped at a tenth of the budget, newest first.
  - The verdict is the last line in the asked-for form (`REPLY:` / `WAIT:` in capitals).
- Failures and fallbacks:
  - A judge that fails, times out or answers without a verdict wakes the agent (fail open), unless `onError` is `"skip"`.
  - Without a judge wired, a judge rule wakes the agent as a debounce of the same quiet period would.
