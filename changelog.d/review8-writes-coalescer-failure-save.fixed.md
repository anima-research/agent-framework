- When a coalesced render's delivery to the store fails while a newer batch of that subject is open, the coalescer now writes the newer batch's fallback mark at once and makes it durable, as it does at a render's start. It went through the host's throttled save (two seconds in the framework), so a crash in that time restored the newer batch as an ordinary pending one and the server was asked to render it again, on top of the render the agent never got. Where the immediate write or its commit fails, the throttled save is asked for, as before.
