- The persistent subconscious's note waiting with a tune-out cancel, when another cancel ends the hold first, now goes out before that cancel's release, and where it can't be written the release says so, with the author and the error, in place of a separate notice: the loss is stored and made durable with the release, or the hold doesn't end and the note waits on, so a store that refused the notice and its record through a stop no longer leaves nothing of the loss.
- A loss told to the persistent subconscious before a stop, in a release or by a notice, no longer loses the turn it asked for to the stop: shown to it at rest, the row was in its window, so the boot's wake for rows still owed counted nothing, and the turn was in memory only. A boot now asks that turn again for each such row its window shows with no turn of the subconscious's after it.
- A tune-out cancel that waited for held writes now delivers its own note once its release is durable and before the hold's end is recorded, and makes the note durable too: the note went out after the end, so a crash between the two lost it untold, the hold no longer on record for the next boot to read. A note kept in memory as it is written (writes held from that write on) no longer counts as delivered: the hold stays in force, the cancel waiting for the writes, and a stop meanwhile tells the note lost.
- A reader's note kept in memory with its waiting tune-out cancel, whose store then failed when the writes were stored, is now told lost to the reader, with the reason, when the hold ends, as the cancel's waiting answer promised. Before, only the operator was told (`message:lost` and the `store-held-lost` alert), and the cancel then ended the hold as if the note had gone out. Where the store can't tell whether the note landed, the reader is told that it may be lost. That holds too where the host stops, or the hold ends without the cancel, before the cancel's run tells it: the notice of that drop, the one a stop keeps in the store for the next boot included, says that whether the note was delivered isn't known, with the error, and not that it was lost. The note isn't written again.
- A reader's note kept in memory with its waiting tune-out cancel, and stored when the writes were stored, now counts as delivered. Its cancel can still wait after that: writes are held again before it runs, or its run fails before it records the end. A stop then told the reader the note was lost though the resident had it, and the next boot wrote that notice. It now tells nothing of the note. A release kept in memory that told a queued note's loss, once stored, is likewise not told again by a stop.
- A host stopped while an operator's change kept a waiting cancel's writes in memory no longer tells the reader its note was lost when that change ends during the stop and stores them. The stop told the note lost first, then waited for the change, whose release stored the note, or the release, or the release telling a queued note's loss: after the restart the resident had the note, or a release said the hold had ended, while the hold was still in force and the reader read that its cancel was lost. The stop now quiets the tune-out timers at once, waits for the operator's changes, and only then accounts for the cancels still waiting, so one whose writes the change stored runs first.
- A note or a release a waiting cancel's run stored is no longer read as kept in memory where writes are held only from just after it (a hold begun as the write returned): the cancel waits for the writes as before, but a stop meanwhile tells nothing of a note that landed. It was judged by whether writes were held after the write, not by what the write answered.
- A loss notice whose own write began a hold was written twice, the kept write stored at the hold's release and the notice written again: it is now written once.
- A boot after a crash now credits the subconscious's own cancel where its call joined another waiting cancel after that cancel's release was written: the release didn't name it, so the notice said a cancel "that wasn't yours" ran, with the subconscious's own note. The run that delivers a queued cancel's note now names that cancel's askers on the note.
- A note whose loss another cancel's release told, that release not made durable then, is now traced (`tune-out:deferred-cancel-dropped`) and the persistent subconscious's turn to read it asked for when the hold ends, by whichever run ends it: it had neither in that process.
- A cancel's release that meets a hold as it is written (a context manager that refuses its work from that write on) no longer records the hold's end over a release kept in memory only: the cancel waits for the writes, the tune-out in force (`{ ok: true, deferred: true }`), and its run once they are stored finds that release and records the end. A stop meanwhile (a trace listener's, of that write) tells the cancel as it tells one it finds waiting, its note's loss kept in the store, rather than its going back on the stopped queue; and a hold such a listener begins on that channel, or a new all-except hold, keeps its timers when the run's own note is then told lost.
- A cancel asked for with a note while an earlier cancel of the same hold was running (from a trace listener, writes held) replaced that one's note when the earlier one waited again: its note, accepted, was dropped untold. The earlier cancel now stands with its note, and the later one's note is told dropped to its author (`tune-out:deferred-cancel-dropped`, `superseded`), its caller having been answered as waiting.
