- In legacy mode, the poison-history breaker no longer sheds a row that the agent's view leaves out, or a `system_change` row, which is the host's. Such a row still goes in two cases: it is part of a stored message that the breaker sheds whole, or it is in a tool result message that answers a call the failing request sent. The rows that the view leaves out include a row that a tune-out holds from residents and a row that a suppress rule took. They also include another agent's stored context injection that isn't marked as a system row. Before, the breaker could remove such a row from the record after repeated inference failures, and count it as a turn set aside. The refusal rewind and a forced `/unstick` use the same shed, so they now pass over these rows in legacy mode too.
- After a stream fails repeatedly, the poison-history breaker sheds only an exchange that the failing request sent. Before, it could remove a row that the request never sent, such as a row stored while the request was in flight. A tool result message that the request didn't send goes with a sent call only if one of its results names that call's id, and then the whole message goes. When the failing request sent nothing that the breaker may shed, it sheds nothing, and it logs that it has no eligible exchange to shed for this failure. When a request fails before its stream exists, the breaker still sheds the newest row that the agent is sent.
