- The heartbeat moves into the framework (`FrameworkConfig.heartbeat`, src/heartbeat/heartbeat.ts). It was the heartbeat-mcpl server: the agent's own periodic check-in, in message or silent mode, and its one-off and repeating reminders. The tools keep the names agents know: `heartbeat--heartbeat_status`, `heartbeat--heartbeat_configure`, `heartbeat--heartbeat_trigger`, `heartbeat--reminder_add`, `heartbeat--reminder_list` and `heartbeat--reminder_cancel`. Wakes are delivered as the server's were: past the gate's rules and through a sleep. A message-mode tick and a reminder store their timestamped text, as before; a silent tick is a silent-heartbeat turn with prose suppressed.
  - State is one file, by default `{storePath}/config/heartbeat.json`: the schedule, the next tick's time and the reminders. The next tick's time is kept across restarts, so a restart doesn't push it back. A tick or reminder that fell due while the host was down fires once, ten seconds after start; a repeating reminder fires once for the periods it missed.
  - `importFrom: { configPath, remindersPath }` brings heartbeat-mcpl's schedule and reminders along the first time, leaving its files as they are.
  - An MCPL server with the id `heartbeat` beside it is refused at create: both would wake the agent and offer the same tools.
  - The reply judge is told the heartbeat's next tick and each pending reminder among what wakes the agent if it waits.
