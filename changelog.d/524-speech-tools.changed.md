- A call of `reply_to_message`, telegram-mcpl's reply, is an explicit send, by that name on any server: it holds the round's plain speech as a send does, where it posted when its answer gives a `channelId` the framework knows, and wherever the speech would go when it doesn't, as telegram-mcpl's plain-text answer doesn't. In locus or hybrid routing, a `code_execution` script that names it makes its round wait before its prose is routed, as one that names `send_message` does.
- `history--extract`'s text form shows a call of `channel_publish`, `send_message`, `reply_message`, `send_dm`, `reply_to_message`, `send_file`, `send_scheduled_message`, `create_poll`, `edit_message`, `say` or `whisper`, by that name on any server, as its name and its words when it carries any, such as `[telegram--send_message] …`, where it showed `[tool_use: telegram--send_message]` with the words left out. A call of any other tool, or one with no words, shows as before. Its description says so, so an agent with the history tools sees its tool list change once.
- The semantic index no longer reads a `text` argument of `send_message`, `reply_message`, `send_dm` or `edit_message`, which no server we know sends them. It reads their `content`, as discord-mcpl and slack-mcpl send it, and keeps reading `channel_publish`'s `text` from its older callers.
