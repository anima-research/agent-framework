- Resident inference has a stall bound on every provider (#268). Each agent turn's stream, the direct Agent API's calls and MCPL servers' inference requests now pass membrane's `progressTimeoutMs`, which ends a provider call that goes that long without a parsed provider event. Keepalives don't count, so a provider that holds a stream open with them while generating nothing no longer hangs a resident with no error, no retry and no trace. Before, the Anthropic adapter's idle watchdog was a resident's only bound, and once keepalive bytes renew that watchdog (antra-tess/membrane#94) nothing bounds such a stream; on other adapters a resident's stream had no bound at all.
  - The bound is `FrameworkConfig.inferenceProgressTimeoutMs`, 30 minutes by default (`DEFAULT_INFERENCE_PROGRESS_TIMEOUT_MS`). The direct API takes `progressTimeoutMs` per call in `InferenceOptions`. A stretch with no parsed event counts as no progress whatever the model is doing, such as thinking a provider doesn't stream, so keep the bound above the longest such stretch you expect.
  - An expiry fails the request as a retryable `timeout`, "No stream progress within <n>ms (inferenceProgressTimeoutMs)": the error policy retries it, each attempt with a fresh deadline, and a stall that persists exhausts the turn with that reason and its classification. Before, a stream that ended on a deadline settled the turn as exhausted ("Stream aborted: timeout") with no retry.
- An MCPL server's streamed inference request whose stream fails or ends on its deadline now gets an error answer with the reason. Before, it got a finished reply (`finishReason: 'end_turn'`) holding whatever arrived before the failure.
