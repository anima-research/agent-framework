- Resident inference has a stall bound on every provider (#268). Each agent turn's stream, the direct Agent API's calls, MCPL servers' inference requests and context-manager's compression calls now pass membrane's `progressTimeoutMs`, which ends a provider call that goes that long without a parsed provider event. Keepalives don't count, so a provider that holds a stream open with them while generating nothing no longer hangs a resident with no error, no retry and no trace. Before, the Anthropic adapter's idle watchdog was a resident's only bound, and since membrane 0.6.0 keepalive bytes renew that watchdog (antra-tess/membrane#94), so nothing bounded such a stream; on other adapters a resident's stream had no bound at all.
  - For agent turns, MCPL requests and compression the bound is `FrameworkConfig.inferenceProgressTimeoutMs`, 30 minutes by default (`DEFAULT_INFERENCE_PROGRESS_TIMEOUT_MS`). The direct API doesn't read that setting: it takes `progressTimeoutMs` per call in `InferenceOptions`, 30 minutes when absent. `Infinity` turns the bound off. A value that isn't a positive number of ms, such as 0, a negative number or NaN, which membrane would read as no deadline, is refused with a `RangeError`: at `AgentFramework.create` for the setting, and before the call for `InferenceOptions`.
  - A stretch with no parsed event counts as no progress whatever the model is doing, such as thinking a provider doesn't stream, so keep the bound above the longest such stretch you expect. A call that streams no events is bounded as a whole: on most adapters an MCPL server's non-streaming request and a compression call, both made with `complete()`, and any call through an adapter that doesn't stream, such as membrane's Images adapter. Membrane's OpenAI Responses adapter in subscription mode streams `complete()`, so there its events renew the deadline.
  - An MCPL server's streamed request that expires is answered "No stream progress within <n>ms (inferenceProgressTimeoutMs)"; a non-streamed one is answered with membrane's own expiry, which says when the call began and how many provider events it had.
  - An agent turn's expiry fails the request as a retryable `timeout`, "No stream progress within <n>ms (inferenceProgressTimeoutMs)": the error policy retries it, each attempt with a fresh deadline, and a stall that persists exhausts the turn with that reason and its classification. With the default policy that is four attempts, about two hours at the default bound. Before, a stream that ended on a deadline settled the turn as exhausted ("Stream aborted: timeout") with no retry. A cancel recorded for the stream still ends it as that cancel, and a caller's `abortInference` now does too, where a `'timeout'` abort used to settle it as a failure. The direct API doesn't retry: it returns an expiry as an aborted result with `abortReason: 'timeout'`.
  - A resident whose turn exhausts on a timeout gets its `[inference-failed]` marker without the advice to change approach, which is about what a request carries and doesn't fit a stall.
