- A silent heartbeat tick that a gate rule batches, the framework's own or the heartbeat-mcpl server's, such as a debounce over `mcpl:push-event` that an operator sets or an agent adds with `wake_add_rule`, now wakes as the tick does when the gate lets it through at once. An agent whose share of the batch is silent ticks alone gets a silent heartbeat turn, prose suppressed, with the tick's separator. Before, it got an ordinary turn, whose prose was routed as speech, and the batch's `[Gate: …]` line named "1 message in (unknown channel)", which the tick never stored. An agent whose share also holds other events gets an ordinary turn, as a tick's wake merged with another's does, and its line leaves the tick out. The tick itself wakes the agents a tick's wake does, not a conversation fork the gate also wakes; the batch's other events wake whom they did before.
  - `GateEventInfo`, which `EventGate.evaluate` takes, gains `silentHeartbeat` (`{ eventId, serverId }`), which marks an event as a silent tick. The framework sets it on its heartbeat's silent ticks, and on a push it has taken for the heartbeat-mcpl server's silent tick by that server's exact marker; nothing else sets it, and an event's `metadata`, a push's `origin` among it, doesn't. Before, the gate had no such mark, and a batched tick was a push like any other.
  - `WakeProvenance`, which the gate hands its `requestInference` callback, gains `silentHeartbeat`, carried by the wake of an agent whose share of a batch is silent ticks alone, whose reason and source are `heartbeat`. Before, every batch's wake had reason `gate:debounce` and source `gate`.
