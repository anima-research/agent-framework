- A silent heartbeat tick that a gate rule batches, such as a debounce over `mcpl:push-event` that an operator sets or an agent adds with `wake_add_rule`, now wakes as the tick does when the gate lets it through at once: a silent heartbeat turn, prose suppressed, with the tick's separator. Before, the batch woke an ordinary turn, whose prose was routed as speech, and its `[Gate: …]` line named "1 message in (unknown channel)", which the tick never stored. A batch holding a silent tick beside other events wakes an ordinary turn, as a tick's wake merged with another's does, and its line leaves the tick out. The batch wakes the agents a tick's wake does, not a conversation fork the gate also wakes.
  - `GateEventInfo`, which `EventGate.evaluate` takes, gains `silentHeartbeat` (`{ eventId, serverId }`), which marks an event as a silent tick. The framework sets it on its heartbeat's silent ticks; nothing else sets it, and an event's `metadata`, a push's `origin` among it, doesn't. Before, the gate had no such mark, and a batched tick was a push like any other.
  - `WakeProvenance`, which the gate hands its `requestInference` callback, gains `silentHeartbeat`, carried by the wake of a batch of silent ticks alone, whose reason and source are `heartbeat`. Before, every batch's wake had reason `gate:debounce` and source `gate`.
