- A failed turn's `[inference-failed]` note no longer gives a reason. It names membrane's type and the HTTP status when it has them, as before, and a safety failure's note names neither. In 0.33.1 it gave the failure's message after "Reason:", cut to 600 characters, and a provider can fill that message with anything, the rejected request included. So a progress bound's cut, a stream's abort, a deadline expiry and a compile that context-manager refuses get no reason in the note either. The note's metadata keeps the message cut to 600 characters, and stderr and `logs/failures.log` keep it cut to 2,000.
- The rewind marker reads the same whether a refusal or repeated failed requests set the turns aside: "The N most recent turn(s) were set aside because the requests that carried them couldn't be completed. Their content isn't shown here, and the originals remain in the raw record." After its `[refusal-rewind]` tag, it names no refusal, filter or category, and it quotes no failure's message. Its metadata keeps `kind: 'refusal-rewind'` and the `category` of its episode's first rewind: the refusal's category, or the failure's message cut to 160 characters. A later rewind in the same episode changes only the marker's text, as in 0.33.1, and `logs/failures.log` keeps each refusal's category.
- An `/unstick` that gives up tells its channel that the agent's requests still couldn't be completed after its rewinds. In 0.33.1 it said the model was "still refusing" and named the refusal's category, which a resident in that channel reads. The category goes to stderr.
