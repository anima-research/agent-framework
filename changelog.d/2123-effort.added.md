- `FrameworkConfig.effort` sets each agent's effort (Anthropic's `output_config.effort`): a level for every agent, or a function of an agent's name and model, asked at each request. `EffortLevel` names the levels, and is exported. A change from one level to another no longer starts the prompt cache over.
  - A request's top-level effort is the agent's base: the level a turn first assembled the agent's request at on its model, kept per agent in `framework/state`. It's kept only for the model of the agent's latest turn, so going back to an earlier model starts a new base there. It's kept only while the agent is live, so an agent resumed after its end starts a new base, at one prompt-cache write. A derived agent starts from its parent's.
  - A different level goes as one effort-only `system_change` row, stored under `'system'` at the start of the turn that answers new user input, after that input and any context injections the start stores. Where a request doesn't end on new user input, the change waits for the next.
  - An agent's requests carry the effort rows the framework wrote for it, or for a voice it inherits. Another agent's effort rows are out of its view, so they're never presented to it, heard at a tool boundary or copied into a derivation of it: `residentViewFilter` and `subconsciousViewFilter` leave them out. A host's own effort rows are left out of the requests. Each row is stored as the framework's own, with `system: true` and `kind: 'effort-change'`, and a server can't set its mark (`effortRowOf`), as it can't set the other keys only the host writes.
  - `undefined` sends no top-level effort and leaves effort rows out of the request. It starts a base of none, and a level after it goes as a row. Where the base was a level, a change to `undefined` takes it off the top, which changes the whole prompt, once. A level after `undefined` changes the prompt from the agent's first effort row on, once.
  - A setting that isn't a level or a function is refused at create. A function's answer that isn't a level or `undefined`, or a throw, counts as `undefined`, and is logged once per agent.
  - When membrane refuses a request's effort rows (`systemChangeRefused`) before the stream's first tool round, the request goes again at once, with no rows and the live level on top. The agent's effort rows that no stored row in its own voice follows are taken back out of the store. That agent's requests go without rows from then on, until it ends or the process does. A refusal after a tool round goes to the error policy instead, and `DefaultErrorPolicy` ends the turn there. A host policy that retries starts the turn's next stream. Either way, the agent's next first request is refused once and goes again at once without rows. Such a refusal needs a request after a tool round that carries a row its stream's first request didn't.
  - `framework/state`'s `effortBases` is never stored over where this release can't read it. A value that isn't a list is left as it is to be repaired, and said once. So is an agent's record of another shape, said once for that agent. A sweep at an agent's end or at a boot keeps every entry it can't read, one without a string `agent` included. So an ended agent's record of another shape outlives it: a later agent under that name reads no base, and gets none stored, until the record is repaired. Each such agent's top-level effort is its live level meanwhile.
  - Rows need membrane 0.10.0, which exports `SYSTEM_CHANGE_EFFORT`. With membrane 0.8 or 0.9 installed, every request goes that way from the start, so a change of level costs the prompt cache as it did through `providerParams`. This is read from this package's copy of membrane, so a host `Membrane` from an older copy beside it leaves the rows unsent, and a change of level never reaches the model.
  - A preview shows the row a start would write, and the direct API sends what a turn would, writing no row.
  - While it's set, an agent whose `providerParams` sets `output_config.effort` is refused where it's created. Unset, the framework's own effort rows are left out of every request, and a host's own goes as stored.
  - **Rollback:** a release without `FrameworkConfig.effort` sends the framework's stored effort rows as the conversation's own. With membrane 0.10, each still sets its level from where it sits, so the last one overrides a top-level effort the host sets through `providerParams`. With membrane 0.8 or 0.9, the native formatter leaves them out of the request. A refusal takes back the agent's rows that no reply follows, so a path that refuses every row, such as Bedrock or the XML formatter, keeps none. The exception is a row followed by one in the agent's own voice that answers no request, such as a puppet's tool call: that row stays. One case remains, with membrane 0.10: an agent whose rows were sent, and whose model then moved to one the API refuses rows on. A release without the setting sends those rows, and the API refuses each request. Move such an agent to a model that takes effort rows before rolling it back.
- The history tool shows an effort row as `[effort: <level> from here]`, and its search matches that text where it matched `[system_change]`.
