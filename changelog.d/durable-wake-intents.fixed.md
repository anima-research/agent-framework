- An agent's `sleep` and its `skip_reply(wake_in_seconds)` self-wake survive a host restart (#627, #194). The gate keeps both in a wake journal beside `gate.json` (`<gate stem>.wake-intents.json`): `create()` restores the sleep before any input flows, and `start()` arms the wakes still ahead and wakes the agent for those whose time passed while the host was down, with the self-wake's notice saying when it was due. A wake that falls due while the host is quiesced is kept for the resume rather than parked in memory, and the host's stop silences the wake timers in its first steps, so a wake due during the stop isn't lost. A restored sleep or self-wake naming an agent the host no longer has is ended rather than quieting the gate for a name that doesn't exist. A sleep, self-wake or `wake` the journal couldn't take still holds in the running process, and the tool result says a restart would not keep it; a journal the process can't read is left in place and not written over.
