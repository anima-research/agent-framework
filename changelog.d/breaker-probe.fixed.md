- The poison-history breaker asks before it sheds. At the hard-down threshold, before it sets any history aside, it sends the failed request again with its messages replaced by one short message, through the agent's auxiliary admission and without membrane's own retries. Only when that probe is answered does it shed as before, newest first, up to its rewind cap; a later failure in the same run of failures sheds without another probe. When the probe fails too, with the failure's own type and status, or in any other way, nothing is shed and no retry is queued, and a `history-kept` ops alert and an `[inference-rewind]` stderr line say whether the request fails without its history too or the probe couldn't tell, with the probe's own answer. A configuration the provider rejects, such as a request setting the model doesn't take, used to cost the person's newest messages, or the agent's own earlier answers, up to the cap, under a marker saying the API kept refusing them.
  - The probe's answer is set aside when the agent has moved on while it was out: its history has been written to, as when a message arrives or a row is edited or removed; another turn, a surgery or a puppet call holds it; its failure count has changed; a surgery holds the store; the store's branch has changed; the agent has been replaced or removed; or the framework is stopping. The next failure decides afresh.
  - `stop()` aborts a probe that's still out and waits for it to settle, within its wait on maintenance, before the store closes. Its doc now also counts the wait on `code_execution` scripts it already made, so with a budget a `stop()` can take up to seven budgets, where the doc said six. A trip after `stop()` has begun, or after the agent was let go, sends no probe and sheds nothing, and so does a failure with no request on the wire.
  - The probe carries each field of the failed request but its messages and its kv-unified wire-receipt hook, so it opens no kv submission, and nothing of it is stored in the agent's context.
