- When a `code_execution` script ends without the answers to some of its tool calls having been seen, because they were still running, or it timed out on them or cancelled them, its result names them, up to ten, and counts the rest by tool, so the agent can tell which effects may still come or came unseen. A call whose answer came after its code stopped waiting is named with the answer's start, and as answered with an error when the answer was one. The lines come in a foreground result's opening lines, after the exit code and the runner's own words, and also in the wake of a background script that dies and in the result of a `cancel`. After an error, a stop or a crash, the first line also counts the calls made while the script ran and those answered while it waited. A call from code an earlier script left running counts in the result of the script running when it's made, and one made while no script runs in the next one's, if its answer hasn't been seen by then. A tool call that times out in a script now raises a `TimeoutError` that says the call was sent and may still take effect, and the tool's description says so too.
- **Hosts:** `PyRunner`'s `ExecResult` carries `calls`, the tool calls made while the script ran, when there were any, as the host saw them when it read the script's end, and `runnerNote`, the runner's own words that end the result, which end `stderr` too, as they did. A foreground `code_execution` result's `structured` carries those lines first, as `tool_calls`, when the result has them. `PYTHON_RUNTIME_SOURCE` sends `{"op": "tool_unwaited", "id": …, "cause": "timeout"}` when the code that made a tool call stops waiting for it at its timeout, and `"cause": "cancelled"` when the script cancels it, which a host that runs the runtime itself can ignore. The `code_execution` tool's description changes, so each agent's prompt cache misses once after upgrading.
