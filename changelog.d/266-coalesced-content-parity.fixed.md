- A coalesced MCPL message with inline images is admitted like any other message (#266). Coalesced `channels/incoming` and `push/event` items, and render results, were checked against a 1 MiB budget on their serialized content, inline base64 images included, which uncoalesced messages never had. Any message with a sizeable screenshot was refused as `coalesce_invalid`, never stored and never woke the agent, and discord-mcpl tags every message create with `coalesce`. Coalescing now checks content's shape only, as RFC-006 keeps content in context: a plain occurrence is delivered exactly as an uncoalesced message is. The 4 KiB bound on `coalesce.data`, which the coalescer holds outside context, is unchanged.
  Every coalesce rejection is now visible on the host as well as on the wire: a `[channel-incoming-rejected]` or `[push-event-rejected]` line naming the server, channel or feature set, message or event id and the failing field, and a `mcpl:channel-incoming-rejected` or `mcpl:push-event-rejected` trace with `reason: "coalesce-invalid"` (or `"coalesce-failed"` when the coalescer itself failed), `field` and `detail`. The wire answers are unchanged.
