- When a turn woken by a debounced gate batch in which no message addressed the agent, and by nothing else that names a channel, routes its plain speech, or a sleep's announcement, with no channel to go to, the agent's `[send-undeliverable]` notice now names the channels the host resolved for the batch's messages (a `chat:system` notice names none), says what came from them didn't address the agent, and says to send its reply to that channel, or one of them, explicitly, giving a channel its server declared inbound-only its own reason in place of that advice. It calls this a routing situation, not a routing/configuration one. Before, it said the turn came from no channel, and to ask whoever runs the host. A batch none of whose channels the host resolved keeps that notice, and so does a turn merged with a batch in which a message addressed the agent in a channel the agent doesn't answer, whose wake now says it was addressed.
