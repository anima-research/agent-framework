It gives that advice only for a channel that can take a send now: a channel the host no longer has registered, one its server declared inbound-only, and one whose server can't take a send each get their own reason in its place, and one whose server this host is connecting or reconnecting to is told to send there once it's back. It calls this a routing situation, not a routing/configuration one, and the reason logged and traced (`mcpl:speech-route-failed`) for it reads `turn has no locus (no channel was chosen for its batch's reply)`, where it read `turn has no locus (no home/trigger channel; nothing to deliver into)`. Before, it said the turn came from no channel, and to ask whoever runs the host. A batch none of whose channels the host resolved keeps that notice.
