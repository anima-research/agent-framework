- **Hosts with provider calls that stream no events and run past 30 minutes:** such a call is now bounded as a whole by `FrameworkConfig.inferenceProgressTimeoutMs`, 30 minutes by default. Before, only the adapter's own timeout bounded it. A call that streams no events has no parsed event to renew the deadline, so one that runs past the bound now fails where before it finished. That covers context-manager's compression on most adapters, which is `complete()` through the membrane agent-framework gives each context manager. It also covers an MCPL server's non-streaming inference request, and any call through an adapter that doesn't stream, such as membrane's Images adapter. A compression that fails this way goes to context-manager's failure handling, and each later attempt fails the same way.
  - **Migration:** raise `inferenceProgressTimeoutMs` above your longest such call, or set it to `Infinity` to run with no bound. A direct-API call takes its own `progressTimeoutMs`.
  - **Unchanged:** a call that streams ends only after 30 minutes with no parsed event, however long it runs. On Anthropic, `complete()` isn't streamed, and the SDK gives each attempt 10 minutes and retries a timed-out one at most twice, so a call there meets the bound only in its third attempt.
