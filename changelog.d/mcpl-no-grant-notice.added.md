- An agent is told when the host refuses a message from an MCPL server that holds no grant. At the first message that the host refuses for lack of a capability, while the server's policy exchange has ended without a grant, the framework writes one `[no-grant]` notice into the agent's context (row kind `mcpl-no-grant`, with `serverId`). The notice names the server and the refused method, says why the server holds no grant, and wakes nobody. The exchange ends without a grant when the policy Request gets no answer or an error answer, when the server refuses the policy (at its first exchange or after a manifest change), when the server declares no MCPL, or when the host's own policy step throws and leaves the connection live. It comes once for each spell without a grant. A transport that drops and comes back with no grant writes no second notice. A connect or a restart starts a new spell, and so does a grant that the server accepted, once it is lost again. The refusal, its error answer, and the stderr line for a refused notification are unchanged.
- `McplServerConnection.noGrantEnd` says how the current transport's policy exchange ended when it ended with no grant (`'unanswered'`, `'errored'`, `'refused'`, `'no-mcpl'` or `'host-error'`), and is null otherwise. While it is set, the connection raises `'no-grant-refusal'` with `{ method, end }` for each message that its admission gate refuses for lack of a capability.
