- When the host refuses a message from an MCPL server for lack of a capability, and the server holds no grant because its policy exchange ended without one, the agent is told once: the framework writes an `[mcpl]` notice into its context (row kind `mcpl-no-grant`, with `serverId`) that names the server and the refused method, says why the server holds no grant, and wakes nobody. The exchange ends with no grant when the policy Request gets no answer or an error answer, when the server refuses the policy (at its first exchange or after a manifest change), when the server declares no MCPL, or when the host's own policy step throws and leaves the connection live. The notice comes once for each connect of the server, a restart's included; a transport that drops and comes back raises none. The refusal, its error answer and its stderr line are unchanged.
- `McplServerConnection.noGrantEnd` says how the current transport's policy exchange ended when it ended with no grant (`'unanswered'`, `'errored'`, `'refused'`, `'no-mcpl'` or `'host-error'`), and is null otherwise. While it is set, the connection raises `'no-grant-refusal'` with `{ method, end }` for each message its admission gate refuses.
