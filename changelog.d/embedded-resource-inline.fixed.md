- MCP's embedded resource, `{ type: 'resource', resource: { uri, text } }` or `{ …, resource: { uri, blob } }`, which RFC-005 §8.1 reads as an ordinary inline block, showed as `[Reference not shown: it arrived without a link.]` on the lanes RFC-005 governs: an MCPL peer's or a module's tool result, a script's view of either, and the push, channel and injection lanes. So its contents never reached the agent. Its contents now show as the block they make: its text as text, and a blob of an image type as an image, of an audio type as audio (in a tool result, the audio marker), and of any other type as a marker naming its type and size. A script's view gets that block too, an image or audio blob as inline data. Its uri isn't shown. One that also claims a disposition is withheld, as inline data that claims one is, and one that claims `never` marks its uri `never` for the result, so a link to that uri in the same result shows its stub. One with both text and a blob, or neither, shows a marker. At any depth in a tool result's data, it's the text its stored copy shows: its uri under `resource` no longer counts there as a reference's. A standard MCP server's result is read as before.
