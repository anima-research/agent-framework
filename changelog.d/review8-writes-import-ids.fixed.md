- The one-release importer of an earlier release's deferred writes writes their record with the id it gives a write that had none before it stores any of them, so when a boot ends before it clears the record, or the store doesn't sync after the import, the next boot finds the write by that id and doesn't store it a second time. When the record can't be written with those ids, each such write stays queued for the next boot, with the writes that follow it for its agent.
