- The one-release importer of an earlier release's deferred writes now writes their record with the id it gives a write that had none before it stores any of them. Each boot gave such a write a new id, so when a boot ended before it cleared the record, or the store didn't sync after the import, the next boot stored the write a second time. When the record can't be written with those ids, each such write stays queued for the next boot, with the writes that follow it for its agent.
