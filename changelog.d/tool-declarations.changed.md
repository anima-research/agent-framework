- kv-unified's immutable-prefix hash takes an agent's tools as JSON writes them, as membrane's request carries them. A field whose value is undefined is left out, where it was hashed as null, and a value that JSON writes as text, such as a Date, is hashed as that text, where it was hashed as an empty object. A host whose tool definitions carry either, built as objects rather than parsed from JSON, gets one fresh layout at the upgrade. On a model that takes a change in its context, the hash is the recorded head's, so a declared change keeps the layout.
- A request that the framework builds for a turn carries a copy of the agent's tools as JSON writes them. A value that JSON can't write, such as a BigInt, now fails as the request is built, and a field that JSON leaves out, such as a function, is left out of the request. The direct API (`Agent.runInference`, `runInferenceWithInjections`) passes the tools that it's given as they are, as before, except where it goes on a recorded head, whose copy it sends.
- A system change row at the end of a request is looked past, as a stored context injection is, when the request is read for how it ends. After the agent's own message the request ends on `[Continue]`, and after tool results its reply follows that tool loop's prompt. Before, a host's change row there, such as one that carries only `effort`, ended the request, with no prompt.
