- With `physicalWindowTokens` set, an agent's first request of a turn is kept within the model's window too, where before only the mid-turn projection guarded it, once a call had reported its prompt. Each compile that builds a request (a stream's start, a retry or restart, the direct `runInference` API, and a preview's dry run) now gives context-manager the request's system prompt and tools as `requestOverhead`, and the window as `requestLimitTokens`, so the compiled context, its injections, the system prompt, the tools and the reply's reserve (the agent's `maxTokens`, unless a caller passes its own budget) come within it, as context-manager prices them. Before, a budget near the window let a turn's first request pass it once the conversation filled the budget, and the provider refused it. A window the system prompt and tools leave no room in now refuses the compile as over budget instead of sending the request. With a window and no `contextBudgetTokens`, the compile keeps the reply's whole `maxTokens` out of the window, at context-manager's default room of 96,000, where it used context-manager's default reserve of 4,000. Without `physicalWindowTokens`, the compile is given the overhead alone, which selects the same as before. Needs context-manager with `requestLimitTokens`.
