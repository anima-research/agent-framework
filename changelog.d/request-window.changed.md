- With `physicalWindowTokens` set, an agent's first request of a turn is kept within the model's window too, where before only the mid-turn projection guarded it, once a call had reported its prompt. Each compile that builds a request (a stream's start, a retry or restart, the direct `runInference` API, and a preview's dry run) now gives context-manager the request's system prompt and tools as `requestOverhead`, and the window as `requestLimitTokens`, so the compiled context, its injections, the system prompt, the tools and the reply the request asks for (the agent's `maxTokens`, whatever a caller's budget reserves for the reply: the limit moves by the difference) come within it, as context-manager prices them. The compile is also given, as `requestOverhead.messages`, what the request may send besides the compiled context: the direct API's tool results ready before its compile, the tool-result guard's pending originals while the batch's audit is durable, the only time the request sends them (the budget's room still keeps out the guard's reserve for them then, at a quarter of their characters beyond their placeholders, and 1,600 an image, as without a window), a `prefillUserMessage`, and the turn a stream's start may end its request on. Outside that price, and reaching context-manager only through its calibration, are the request-only turns rendered again before earlier replies, which grow with the silent ticks the window keeps (69 tokens each by context-manager's estimator), another agent's rounds sent as transcript lines, a tool result that becomes ready during the direct API's compile, which only a framework-driven turn on the same agent can bring, and what membrane adds as it renders the request. Before, a budget near the window let a turn's first request pass it once the conversation filled the budget, and the provider refused it. A window the reply, the system prompt, the tools, those messages and the message injections leave no room in now refuses the compile as over budget instead of sending the request. The turn ends with `errorType` `window_full`. So does a reply that leaves the window no room by itself, refused before the compile. The turn kicks no compression drain, doesn't unpin the turn's inputs or roll back a budget, and its `context-refusal` alert says what would make room before it gives the reason. The agent is told that trying again won't make room, and who can. With a window and no `contextBudgetTokens`, the compile keeps the reply's whole `maxTokens` out of the window, at context-manager's default room of 96,000, where it used context-manager's default reserve of 4,000. The runtime settings read that budget, 96,000 plus `maxTokens`, as the live one, so a `contextBudgetTokens` under it lowers it. Without `physicalWindowTokens`, the compile is given the overhead alone, which selects the same as before. Needs context-manager with `requestLimitTokens` and `RequestOverhead.messages`.
