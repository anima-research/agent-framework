- **An MCPL server's `initialize` error whose `message` isn't a string no longer reads `undefined` or `[object Object]`** (#750). Before, `{ code: -32603 }` gave `MCPL server "<id>" initialize error: undefined`, and a message that is an object gave `... initialize error: [object Object]`. Now both give `MCPL server "<id>" initialize error: the server answered without saying what went wrong (code -32603)`, the way an error answer to a request after the handshake treats a message that isn't a string. A blank message reads the same way, and the code is left out unless it's a number. A string message still reads as the server's words, redacted, then trimmed and bounded.
