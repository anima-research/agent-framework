- **The turn-opening pin and an undeclared stream read the window (#291).** 0.31.0's turn-opening pin (`agent-framework:turn-inputs`) pins the rows the agent sees that were stored after its newest own message and its consumed watermark; here the rows are the agent's *window's*: those presented to it since its mark, in the window's order, a row stored before the mark and presented after it included, and no row stored and not yet presented, which isn't in its window (in legacy mode, where the window is the record, the rows stored since). A mark taken before the window was written down (an agent registered where its window wasn't yet written down holds one until its first compile) is read the same way once the window is: a row presented to the agent again after the write-down is among the turn's rows, and so are the rows it hadn't read before it. And 0.31.0's rule that a stream whose tool calls don't declare `supportsInjectedMessages` carries no injected messages reads here as: what arrived for the agent during its turn waits out of its window for the turn's end; a tool boundary with no stream, as the direct API's, presents what arrived.
