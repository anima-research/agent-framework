- **A turn's end stops typing at its own server and channel, and no longer everywhere.** The end of a turn used to stop the typing indicator in every channel of the process, whether the turn completed, failed, was stopped or was dropped. So it ended another agent's indicator, a resident's indicator during a subagent's run, and an indicator that a host started through `framework.channels`. Now an indicator at another address keeps typing. A failed stream that the error policy retries no longer stops the retry's indicator, and the retry's own end stops it. Some ends stopped no indicator, and the next turn's end, anywhere in the process, stopped it instead. Each of these now stops the turn's own indicator. They are a continuation that fails to start, such as at its checkpoint write, and an agent's removal or an ephemeral run's end while its turn is open. That holds also when the turn's stream never answers its cancel. An agent that takes over a name keeps its indicator at the same address when the old agent's last stream ends, or when the old agent's start is dropped. When a removed agent's stream ends late, it sends no second stop. A host that starts typing through `framework.channels` stops that typing itself. The framework's `stop()` now sends a stop to each indicator that is still running, where it used to clear them without one. A turn that types at the same address as a host still stops that indicator at the turn's end. The registry keeps one indicator per address, with no owner, so two typers at one address still share it, and the first stop ends it for both. `ChannelRegistry.stopTyping()` with no channel still stops every channel. A host's own module can still stop an indicator at any agent's stream end, as connectome-host's activity module does. An address that its server removes and registers again is the same address, so an old turn's stop still reaches a new indicator there.
