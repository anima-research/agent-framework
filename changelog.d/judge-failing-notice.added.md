- An agent is now told when a rule's reply judge keeps failing. When the judge fails 3 times in a row for one wake rule, the gate writes a `[Gate]` notice. It writes it as it writes a batch's row: into the delivery agent's slot, with the audience that the batch's events name. Where they name none, it is a write that names no agent. But where an agent already has an open notice, the write names the other agents. The notice names the rule and gives the newest failure in the words that `gate_status` gives. It says what the rule's batches now do: under `onError: "wake"` they are delivered with no judgement, and under `"skip"` they don't wake the agent. The row's kind is `gate-judge-failing`, and it carries `policyName`. When the judge next gives a verdict for that rule, a second notice, of kind `gate-judge-answers`, says that the judge answers again. The gate writes it to the agents that the failing notice went to. Neither notice wakes anybody. Under `"wake"`, the gate writes the failing notice first, and then the batch wakes the agent.
- A failing batch can reach nobody, because each of its events is held or names no recipient. The gate writes no notice for such a batch. The notice comes with the next failure that reaches an agent. Each agent has one such notice open at a time, for the first rule to reach 3 failures in a row in a batch that reaches it. While an agent's notice is open, the failures of another rule write no notice for that agent. `gate_status` shows those failures. Another agent's open notice doesn't stop a notice to an agent that has none. A notice ends without a second notice when its rule is removed or its behavior changes. A judgement counts for a rule only where the rule still has the judge that made it. A call that was out when the rule changed or was removed, or a batch judged later with the old judge, changes none of the rule's counts in `gate_status`. After an agent's notice ends, a rule that has failed 3 or more times in a row writes a new notice for that agent at its next failure. That failing batch must reach the agent. A failing notice that can't be written is logged, and a later failure of the rule that reaches an agent tries again. An "answers again" notice that the gate can't write is tried again when the judge next answers for the rule. The notices are kept in memory, so a host that starts anew can tell them again.
- `wake_add_rule`'s description of `judge` says that the host tells the agent one time when the judge keeps failing for a rule.
