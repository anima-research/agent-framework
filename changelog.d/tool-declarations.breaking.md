- **Hosts that store their own `system_change` rows:** an agent on its head (`toolDeclarations: 'head'`, the default) no longer sends them.
  - **Who needs to act:** a host whose change rows reached its model before. They now stay out of the requests and the compile of every agent on its head, whose context manager the framework opens with a view that leaves them out: a resident's, an ephemeral agent's, isolated or derived, a resumed agent's and a conversation fork's. The persistent subconscious, whose view merges the residents' slot, carried a host's change rows from that slot before; it now leaves out every change row not its own, whatever its principal's setting. A request through the direct API (`Agent.runInference`, `runInferenceWithInjections`) carries them only under `'entries'`, as the agent's requests do, and the agent's own change rows only where it goes on the agent's recorded head. A module's view lookup (`ModuleContext.viewKeeps`) follows the requests, so a module that reads it, as history's window marks do, finds such a row kept only where the agent's request carries it: it now answers false wherever the request leaves the row out, an agent on its head included, where it answered true. It answers the change rows agents stamp as their own the same way.
  - **Migration:** set `toolDeclarations: 'entries'` on the agents that should send them. Under `'entries'` a host's change rows go out as stored in the requests the framework builds for an agent's turns; the direct API carries them too, with the agent's own change rows where what its caller passes is what the agent's recorded head and own change rows declare, so its request goes on that head as the agent's do, and without them elsewhere; no setting sends them to the subconscious. Membrane sends a change only where the formatter's `rendersSystemChanges` and the adapter's `sendsSystemChanges` both hold, as the native formatter's and the Anthropic adapter's do, and an adapter wrapped in another needs the wrapper to declare `sendsSystemChanges` too. Membrane refuses any other request carrying a change before sending it, and the agent then keeps to its head until it's built again. It needs no sibling version beyond this release's own ranges (`@animalabs/membrane` `^0.8.0 || ^0.9.0 || ^0.10.0`, `@animalabs/context-manager` `^0.27.0`).
  - **Unchanged:** the rows stay stored, and an inspection (`inspectAgentContext`) still shows them.
- **Hosts with a table or `switch` that must cover every `TraceEvent['type']`:** `TraceEvent` names 3 more types, `head:declared`, `head:moved` and `head:resend` (under Added), so a `Record<…>` keyed on it, or a `switch` checked exhaustively with `never`, needs an entry for each.
  - **Migration:** add an entry for each of the three.
  - **Unchanged:** every other trace type, and their fields. No sibling package needs a new version.
- **Hosts that handle every `presentation:retracted` reason:** `PresentationRetractReason` has a new member, `'head-moved'`.
  - **Who needs to act:** a host whose code covers each value the trace's `reason` can take, such as an exhaustive `switch`. It meets `'head-moved'` when a move of an agent's recorded head takes that agent's own system changes out of the record, and they leave another agent's window that held them, such as one that observes the agent. The `head:moved` trace after it says which move it was, and none comes where no head was recorded and the new one couldn't be stored.
  - **Migration:** handle `'head-moved'`, or let a default branch take it. It needs no sibling version beyond this release's own ranges.
  - **Unchanged:** the other reasons, and the trace's fields.
