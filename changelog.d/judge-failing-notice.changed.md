- A reply judge's failures in a row are counted for each wake rule, and a verdict for another rule no longer resets them. When a rule's behavior changes, its count starts again from 0. `gate_status`'s note on a judge that keeps failing now comes once for each rule with 3 or more failures in a row, and names the rule. Before, the gate kept one count for all its rules. So a rule whose judge failed each time got no note while another rule's judge answered in between.
- Where a reply judge is wired, `wake_add_rule`'s description of `judge` changes. So the tool definitions in an agent's requests change. A summariser's requests that declare the agent's tools change too. Where prompt caching is on, the cached prefixes of those requests are written again once, at the first request after the update.
