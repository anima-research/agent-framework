- A reply judge's failures in a row are counted for each wake rule, and a verdict for another rule no longer resets them. A rule whose behavior changes counts afresh. `gate_status`'s note on a judge that keeps failing now comes once for each rule with 3 or more failures in a row, and names the rule. Before, the whole gate had one count. So a rule whose judge failed each time got no note while another rule's judge answered in between.
- `wake_add_rule`'s description changes, so the tool definitions that an agent's requests carry change too. Where prompt caching is on, each agent's cached prefix is written again once, at its first request after the update.
