- On a model that takes a change in its context, an agent's requests keep its tools and system text at a recorded head. A later change to its tools, or system text added after the head's, is stored as one `system_change` row at the end of its context, so the change no longer rewrites the provider's cache from the head (README: "Tool declarations"). membrane decides which models take a change (`Membrane.takesToolOrSystemChanges`, from membrane 0.10.4), by the request's formatter, its adapter and the model. There is no setting. An adapter that wraps another must declare `sendsSystemChanges` itself. With an earlier membrane, which this release's range admits, no model takes a change. A change row is a `system_change` row that changes tools or system text; one that carries only `effort` is not.
  - The head is recorded for each agent and branch: in the store, or in memory for a bounded job. An agent whose `spec.inherit` names a running agent and no `atSequence` starts with a copy of that agent's record, as `deriveAgent`'s child and a conversation fork of a template do. So a copy of that agent's context reads that agent's cache, and declares only its own difference.
  - A request folds the head that it carries with every change row in its messages, whoever stored the row. The result must equal the agent's current tools, each by its name and its definition, and its current system text. The tools' order isn't declared. Otherwise the request goes in a fallback form, on the agent's current tools and system text with every change row left out of its messages, and the next request tries again. System text is a sequence, which a request carries as one text: where the agent's first blocks join to the declared text, the blocks after them are an addition, and any other change replaces it. A change row stored during a turn joins the request that starts the next turn.
  - A move records the agent's current tools and system text as its head, and takes the change rows that its context can remove out of it. The head moves when no head is recorded, when the system text is replaced, when the store doesn't take a change row, when a compile is refused over budget with change rows kept, and for cost. The rule for cost moves the head when the reads of the tool definitions that a move would take out have cost about as much as the move costs at this compile. It reads membrane's prices (`Membrane.pricingFor`) and the agent's count of answered requests, one for each round of its own streams, and measures sizes in characters. On a model that may bind its thinking, a move for cost never sets kept thinking aside. A move that the budget forced raises the `head-consolidated` operator line.
  - A request that carried a change row, and that membrane marks as refused for it, goes again on the agent's current head. After a 400 that membrane doesn't mark, other than for `context_length` or `auth`, the request goes once more in the fallback form, and an accepted retry takes the change as the cause. Either way the agent keeps to its head until it's built again, and the framework raises the `head-resend` operator line.
  - A request through the direct API (`Agent.runInference`, `runInferenceWithInjections`) stores nothing and moves no head. It goes on the recorded head where its fold comes out right, and otherwise in the fallback form.
  - New trace events: `head:declared`, `head:moved` (with its `why`, and a move for cost's estimated figures) and `head:resend` (with its `diagnosis`). `presentation:retracted` gives the reason `'head-moved'` when a move's removal takes change rows out of another agent's window.
  - A change row that an agent stores is that agent's context, as its stored injections are. Another agent's view leaves it out, and the readers that pass over a stored injection as context pass over it too, such as a conversation fork's seed and the history module's semantic index.
  - `isSystemChangeMessage(message)` is exported. It says whether a row holds `system_change` blocks, from its blocks alone, whatever metadata it carries.
  - `Agent.mayBindThinking` says whether a choice that could set kept thinking aside treats the model as binding: true unless `thinkingBinding.binds` is `false`. `UsageTracker.requestCountOf(agentName)` gives an agent's count of answered requests: each round of its own streams whose usage membrane reports, stored with the usage state.
- `agent-framework-recover --store <path> --remove-system-changes`, with the host stopped, takes every change row (one that changes tools or system text) out of every message slot of the store, on a new branch made at the head of the current one, which it selects for the removals. On a failure it selects the source branch again. If it is stopped partway, run it again: it takes the rest out, on a branch of its own. Run it before stepping back to a release before this one, which sends a stored change row as stored, beside its own tools, or, with membrane 0.10.0 or later and a formatter or adapter that can't send a change, has membrane refuse the request. Run after such a step back, it mends the store. Other branches keep their rows, and `--dry-run` counts each slot's rows.
