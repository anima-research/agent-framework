- A message a tune-out holds from the residents is no longer injected into a resident's live turn. One that arrives while the resident's turn is alive is held, and the next tool boundary stored it and injected it into the turn with the other held writes, though the resident's compiled view leaves it out. The boundary now stores it without injecting it.
- A module's `ctx.queryMessages` and `ctx.getMessage` now mark such a message with `heldFromResidents: true` (on `ModuleMessage`): a message that arrived in a tuned-out channel, stored with `metadata.tuneOut`, whose row no resident is shown, during the tune-out or after it. A module's context answered it as an ordinary row, so a module that leaves out `held: true` rows to keep to what the residents see took it in. A held write that carries the stamp is marked as well as `held`, and so is its stored row once it lands. Its text can still reach a resident in rows of their own, which aren't marked, such as the cancel's `<tuned-out-backlog>` row, with the text of the last `backlogCap` of the tune-out's messages, the stored ones first and then those still held, what the subconscious says of it, and the result of a tool that reads history on request.
- A cancel's `<tuned-out-backlog>` now carries the tune-out's messages still held, oldest first, after its stored ones. It carried only stored ones, so a message held while the resident's turn was alive was left out of it. The held messages the cap leaves out, all of them when `backlogCap` is 0, now follow the subconscious's cancel report notice, each a row of its own with its own content, since its view holds only stored messages. So does a held message the backlog shows whose image or audio its text lines drop. A cancel the subconscious makes itself now gets that notice and a report turn too when any held message follows the notice, since it wrote its note, if any, before it could see them.
- A cancel the subconscious makes itself with no note now gets the report notice and a report turn when the cap left messages out of the `<tuned-out-backlog>`. It got neither, so at `backlogCap` 0, where the tool says the subconscious's report is the whole delivery, the resident was left an empty backlog and nothing else.
