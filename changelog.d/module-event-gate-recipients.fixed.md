- A module's process response that asks inference for named agents, for an event other than an MCPL push or channel message (those are gated as they arrive): when a gate rule batches the event (`debounce`), it now wakes only those of them that its source can trigger and that read the slot its messages land in, and the batch's `[Gate: …]` line quotes the event to them alone. Before, it woke every agent the gate wakes and was quoted to each of them, outside its messages' audience. A named agent that doesn't read that slot, such as an isolated job, isn't woken by the batch, since a line for agents none of whom read the slot is stored as a write that names no agent, which every resident reads; with no rule batching the event, inference is asked for it as before. A response asking inference for every agent (`requestInference: true`) is unchanged. One asking it for an empty list (`requestInference: []`) now wakes no one in a batch, as it wakes no one when nothing batches it.
- In a gate batch that also holds events naming their recipients, an untargeted event, one with no list of recipients, is now shown only to the gate's own recipients, and an event naming its recipients only to them: a named recipient the gate doesn't otherwise wake, such as a subconscious, no longer gets the batch's untargeted events in its line. An event whose list of recipients is empty appears in no line and goes to no reply judge, and leaves the rest of its batch as it would be without it. A judge rule asks the reply judge about the agents its batch would wake, and isn't judged when it would wake no one, and an agent's upcoming wakes count a pending batch only when it would wake that agent.
