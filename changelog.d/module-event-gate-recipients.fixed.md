- A module's process response that asks inference for named agents: when a gate rule batches its event (`debounce`), the event now wakes only those of them that its source can trigger and that read the slot its messages land in, and the batch's `[Gate: …]` line quotes it to them alone. Before, it woke every agent the gate wakes and was quoted to each of them, outside its message's audience. A named agent that doesn't read that slot, such as an isolated job, isn't woken by the batch; with no rule batching the event, it's woken as before. A response asking inference for every agent (`requestInference: true`) is unchanged. One asking it for an empty list (`requestInference: []`) now wakes no one in a batch, as it wakes no one when nothing batches it.
