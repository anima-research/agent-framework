- In a tool result, a link (MCP's `resource_link`) the host can't fetch whose uri may carry a credential now shows a stub that says why it can't be fetched, with no uri, where the result's JSON showed the uri. So an agent no longer sees that uri, and has no other handle on the link here. Such a uri has userinfo, or a query or fragment parameter that has a value and is named like a signed URL's or a token, such as `X-Amz-Signature`, `sig`, `hm`, `token`, `access_token` or `key`, compared by letters and digits alone, so `accessToken` and `token[]` count too. RFC-005 §5 gives the reason: signed URLs and query capabilities are bearer credentials that look like locations. An ordinary link with a query, such as `watch?v=…`, and an anchor such as `#token`, which has no value, still show their uri.
