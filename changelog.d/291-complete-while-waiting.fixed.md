- When a stream completes while its round's tools still run, the round and its results are now stored back to back, as at an ordinary tool boundary. Each call still running gets an error result as before; the results are then built first, a spilled result's workspace write included, and the round and its results are stored after the build with no await between. Before, the round was stored ahead of the build and its results after it, so a write that isn't deferred and landed meanwhile, such as another resident's own row in the shared slot, a module's `tool_result` or a channel's row in a fork, was stored between the round's `tool_use` and its result. Such a write is now stored before both. While the results are built the round stays the agent's pending round (`getPendingAssistantRound`), as during an ordinary boundary's build, and a child derived meanwhile (`deriveAgent`) is framed with the round and the results the agent holds: each that came in, and the error result of each call still running.
