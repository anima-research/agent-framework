- `sourceBodyDigest`, and the `storedBodyDigest` it stamps at ingestion on both MCPL lanes, now take each block's stored form from context-manager's own `blockAsStored` (context-manager 0.22.0) instead of a copy of its transform (#252). MCPL's content conversion produces only text, image and audio blocks. Every other body in the real-store test, those shapes among them, hashes as it did under the copy, and the test pins each one's digest. Three other shapes now hash differently:
  - a `tool_use` whose input isn't an object, which the store hands back with `input: {}` and the value kept in `unparseableInput`;
  - media whose data is a byte array, which the store keeps as base64;
  - a media block the store refuses (no media type, and for an image no recognized signature), which is now digested as given, where the copy re-encoded its data and dropped its other fields.
- Digests already stamped are never recomputed. A stored copy of a body of the first two kinds, stamped under 0.24.0 or later through the copied transform, keeps that digest and doesn't match it. So for such a copy, a mismatch doesn't mean it was changed after it arrived, as the 0.24.0 entry reads one.
- A digest is now a digest under the context-manager release that computed it: a release that changes what the store keeps, such as its set of image signatures, changes the digest of a body it touches.
- The digest takes each block's stored form on its own. When the store mends a `tool_use`, it also releases a raw replay form (`rawXml`, `rawItem`) that other blocks in the message share, so a body like that doesn't hash as its stored copy does.
