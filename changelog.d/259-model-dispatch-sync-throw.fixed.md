- A throw in the dispatch of a model's tool call no longer fails the turn (#259). The call gets a failed result instead: `NAME failed in the host: MESSAGE; it may have taken effect`. A handler can answer the call and then throw. The model then gets the handler's answer. The other calls of the response run, and the turn goes on. The throw now shows as a `tool:failed` trace with module `framework`, and not as `inference:failed` and `inference:exhausted`. So a monitor that counts only failed inferences no longer sees it, and the throw no longer adds to a streak of failed turns. A tool-lifecycle observer with access to the call gets `started` and then `failed`. These events are sent as best effort, as other lifecycle events are. A stderr line names the agent, the tool and the call's id.
- `sleep` now refuses a sleep whose end is too late for a JavaScript date (#259). It keeps a margin of one day. The refused call changes nothing, and a sleep already in force stays. Before this fix, an end past the date range set the gate, and then the call threw. On the model's path, the turn then failed.
