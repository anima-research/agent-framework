- An MCPL server whose `tools/list` fails during a re-list keeps the tools it last listed, while its connection still serves it (connected, or reconnecting), instead of vanishing from the tool list. Every reconnect re-lists all servers, so one connector reconnecting while another was briefly down removed the second one's tools: a full prompt-cache rewrite (the tool list tops every request), the tools missing unannounced, and a second rewrite when they returned. A call to a down server fails on its own, as before. A modern MCP server's tools still leave the list while it isn't connected or its listing fails, as before.
  - **What's kept:** each tool the server last listed, offered or not, as the list stands when the re-list publishes, with its feature set and the server its calls go to. Only names that begin with the server's tool prefix now, and that its tool policy now allows, are kept. The class the server declared for it (RFC-008) isn't kept, so unless an operator's class override applies, it's unclassed, the restrictive answer, until the server lists again.
  - **What isn't:** a server halted for good or closed by the host keeps nothing, nor does one that stops serving before the re-list publishes. A server whose handshake advertised no MCP tools keeps nothing, connected or reconnecting; a connected one has listed nothing, as before.
  - **The log:** each re-list that publishes logs one line for each server whose listing failed and whose handshake advertised tools, saying how many known tools it keeps, or that none of its tools are offered, with the server's error text redacted as other server errors are. Nothing is logged once `stop()` has begun.
- A `tools/list` answer holding an entry that isn't an object with a string `name` is refused whole, as a page with no `tools` array already was, so it changes nothing the host believes. Every version through 0.32.0 published the tools read before such an entry, and since RFC-014's tool hints the page's other entries also reached the server's toolset presence; now the server keeps its last good list, and a move between its tool list and its toolsets waits for the next listing that is read whole. `McplServerConnection.sendToolsList` rejects such a page with an error naming the entry's place, where 0.32.0 returned the page with the entry in it. A server that keeps sending such an entry keeps its last good list, and each re-list's line says its listing failed.
