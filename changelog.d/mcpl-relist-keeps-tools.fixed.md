- A server whose `tools/list` fails during a re-list keeps the tools it last listed, while its connection still serves it (connected, or reconnecting), instead of vanishing from the tool list. Every reconnect re-lists all servers, so one connector reconnecting while another was briefly down removed the second one's tools: a full prompt-cache rewrite (the tool list tops every request), the tools missing unannounced, and a second rewrite when they returned. A call to a down server fails on its own, as before.
  - **What's kept:** each tool the server last listed, offered or not, with its feature set and the server its calls go to, under the tool prefix and tool policy in force now. Its RFC-008 class isn't kept, so it's unclassed, the restrictive answer, until the server lists again.
  - **What isn't:** a server halted for good or closed by the host keeps nothing, nor does one lost before the re-list's tool list is published. A connected server whose handshake advertised no MCP tools has listed nothing, as before. A listing that answers but breaks off partway, such as at an entry that isn't a tool, keeps the known tools whole, where it used to publish the part read before the break.
  - **The log:** each re-list that keeps a server's tools logs one line saying so, with the server's error text redacted as other server errors are.
