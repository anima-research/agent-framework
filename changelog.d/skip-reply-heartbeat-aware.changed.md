- `skip_reply` with `wake_in_seconds` names the heartbeat's wake when it comes first. When the heartbeat's next tick or a pending reminder is due before the self-wake, and the agent's rules let it wake the agent, the confirmation says so instead of promising the self-wake: `Turn ended; nothing sent. Your heartbeat (a check-in prompt, every 10 min) wakes you first, in ~300s, and that wake cancels your ~900s self-wake: set it again then if you still want it.` Any turn start cancels a pending self-wake, so the heartbeat's turn ends it. A skip with no wake, a self-wake due first, a wake the rules hold back, an agent the heartbeat doesn't wake, and a host whose `gate.js` may decide (the gate consults it before the rules, which a probe can't) read as before.
  - The gate is asked about each tick and reminder as the event its delivery is judged by: a silent tick as silent, each with the text it will bring. A rule on the content or the silent flag now decides the reply judge's list, and the note, as it will decide the wake. Before, both kinds were probed with the placeholder text `probe`, so a rule telling ticks from reminders by their text (they share the server id `heartbeat`) went unseen.
  - `Heartbeat.upcomingWakes()` gives each wake's `kind` (`heartbeat` or `reminder`), `silent` and `text`, and takes an optional `whose` (`"its"`, the default, as the reply judge is told, or `"your"`); the `HeartbeatUpcomingWake` type is exported. `EventGate.scriptMayDecide()` says whether a `gate.js` may decide the next event.
