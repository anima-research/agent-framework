- **Operators of a workspace with a nested mount, on a disk that tells names apart:** where the nested-mount checks can't tell apart two names that the disk keeps apart, they now err toward the nested mount, so that on a disk that folds names the outer mount can't write into that mount's directory unseen. A name the outer mount read and wrote as its own is now taken for the nested mount's directory: every tool that names it is refused as a path that may lie in the nested mount, with the two spellings the workspace can't tell apart and a step for each thing the caller may have meant, and walks and pushes pass over it. Where a followed link leads outside the mount, the refusal says only that it can't tell. That's:
  - on a disk that keeps the Unicode normalization forms apart, as ext4 does, a directory or file named in the other form of a nested mount's directory's name, at any level;
  - at a level that folds case, or whose own entries told nothing at start, a name the comparison folds with it that the disk keeps apart, such as `ss` beside a nested `ß`, or `ı` beside a nested `i`, or, on a disk that folds case but keeps default-ignorable code points apart, a name that differs from a nested directory's only by one, such as `inner` with a soft hyphen or a zero-width joiner inside, which the comparison takes for `inner`, as Linux's casefold does;
  - a name in another case than a nested mount's directory, beneath a directory whose own entries didn't tell at start how it folds. Such a level counts as folding until a start finds a name there that tells. A directory's entries don't tell where it's empty, holds no name with a letter a-z or A-Z, isn't made yet or can't be listed, or where a lookup in it fails for another reason than that nothing is there, or a name changes while it's read, or where each such name it lists is beside a twin spelled with every letter in the other case and no pair of them tells. A pair doesn't tell where the two are one file, as hard links, or each has only one letter a-z or A-Z, or the name with only its first letter in the other case is there too, or the directory is on a filesystem whose change times the workspace doesn't trust (off Linux, every one; on Linux, all but ext2, ext3, ext4, xfs, btrfs, tmpfs, f2fs, zfs and overlayfs). Above every mount's root, reached through a link, the nested directory's own name is read alone, and it doesn't tell where it isn't made yet or has no letter a-z or A-Z, or where it has such a twin as another file that doesn't tell in one of those ways.
  - **What to do:** where the name differs from the nested directory's only in the case of letters a-z or A-Z, beneath a directory that told nothing at start, start the workspace again once the nested mount's directory is made, and if the refusal comes again after a start that found that directory there, rename one of the two spellings, since such a level can tell nothing with that directory in it too; otherwise rename one of the two. The refusal says which applies and names both spellings. Where two mounts' roots are configured in spellings the workspace can't tell apart, start places the nested mount by a guess, and the refusal asks for the configuration to be checked.
  - **What the outer mount already held there** stays in its history, and no push of the outer mount writes it. Where the mounts' includes cover it, a listing shows it with the same note.
