- An agent's own row whose store threw after the row landed (context-manager's `WriteLandedError`), or threw with an outcome the store couldn't tell (`WriteOutcomeUnknownError`), now enters the agent's window as its write would have, and then the error is passed on as before. This covers the agent's rounds, its tool results (with the tool-result guard on or off) and the rows the framework writes as the agent's own (`storeOwnRow`). Before, such a row stayed out of the window until the agent's next turn start or tool boundary, so an own row written after it entered the window ahead of it. Of the rows a `WriteOutcomeUnknownError` names as possibly stored, only those the store reads as held are presented.
- Where the read of whether those rows are held throws, every row a `WriteOutcomeUnknownError` names is now offered to the agent's window, as `addMessage` offers them: a row the window can't take yet is kept and presented ahead of the agent's next own row, and one the store doesn't hold is dropped. Before, none of them was offered, so a landed row whose error named it only as possibly stored entered the window behind an own row written after it.
