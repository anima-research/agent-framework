- A reader's note waiting with a tune-out cancel is no longer lost untold when the host crashes, or stops while the store refuses the notice of its loss: each stop now stamps the holds it leaves on record whose waiting cancels it accounted for (`tune-out/<primary>/stop-stamp`), and each boot stamps its own run as covering none, trying again until the store takes it, the subconscious's waiting `cancel_tuneout` answer saying meanwhile that a stop or a death while the store still refuses may go untold. A store with no stamp at all, as one an earlier version wrote or one that refused every stamp, counts as stopped cleanly. For a hold on record the stamp doesn't cover, the boot reads that run's rows up to its own start, the residents' and the subconscious's own (its stored rows where its window isn't presented), and tells the persistent subconscious what they show: that a cancel ran, its release stored and its end not recorded, crediting the subconscious's own cancel or another's by its reason, and then whether its own, asked for, had not run, with its note; that its note was delivered; that the cancel it asked for, its own `cancel_tuneout` of that hold answered as waiting, was lost, quoting the first line of its note; or, where nothing shows, that a cancel it asked for then, if any, was lost with any note. A release the boot itself makes (an end time passed, a wake budget spent) isn't read as that run's. A release that already told the note's loss, or a loss the stop kept in the store, gets nothing more; a bare channel id two servers' holds answer to names neither, and the waiting answer now names the server (`serverId`); a later boot tells a hold again where it finds more, or an ask made after it was told, and asks the subconscious's turn once. The notice is kept and tried again while the store still refuses, and is traced as `tune-out:stop-unrecorded` (`found`: `ran`, `delivered`, `asked` or `unknown`).

- A boot now writes its run's stamp only once the notices it tells of the last stop's are written to the subconscious or kept in the store, and while one is neither, the stamp still bounds the next boot's reading at the last run's start: written first, a crash or a refused record between the two left the next boot telling the hold conditionally, where that run's rows said more. A stop meanwhile (a trace listener's, of a notice's write) keeps its own stamp: no marker of the run is written over it. So does a branch move meanwhile (a failed surgery's restore to the branch it was on), and a boot whose telling of the last stop's stamp throws partway keeps that bound for the run, so the next boot tells the holds it didn't reach from the rows they had.
- The stamp names the branch its run's start is on (`branch`), and a branch move writes this run's stamp on the branch moved to, from that branch's head (or where this run began on it, for one it was on before): a cancel waiting there and lost to a crash is told though that branch's own stamp covered the hold, and an earlier run's rows there aren't read as this run's. A stamp whose start is on another branch than the boot's bounds nothing: each hold it doesn't cover is told conditionally. After a move, the loss record written there first reads in the notices that branch kept, which it wrote over; where this run keeps any, it is written at the move, before the stamp, and the last stop's bound stays where that branch's record can't keep them.
- A boot's notice of an unrecorded stop no longer gives a second row where the boot before wrote the same one from the store's record on a quiesced boot, its window not holding it yet, or where the release it tells of was the last row that boot read (a notice now silences what was stored up to the head it was decided at, not only before it). - The loss-notice record and each stamp, the stop's and each run's, are made durable as they are written (the store's sync), the record before the stop's stamp that counts on it: they were left to the store's periodic sync, so a crash before it found an older record or stamp.
