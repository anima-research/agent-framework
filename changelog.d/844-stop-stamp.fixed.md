- A reader's note waiting with a tune-out cancel isn't lost untold when the host crashes, or stops while the store refuses the notice of its loss: each stop stamps the holds it leaves on record whose waiting cancels it accounted for (`tune-out/<primary>/stop-stamp`), and each boot stamps its own run as covering none, trying again until the store takes it, the subconscious's waiting `cancel_tuneout` answer saying meanwhile that a stop or a death while the store still refuses may go untold. A store with no stamp at all, as one an earlier version wrote or one that refused every stamp, counts as stopped cleanly. For a hold on record the stamp doesn't cover, the boot reads that run's rows up to its own start, the residents' and the subconscious's own (its stored rows where its window isn't presented), and tells the persistent subconscious what they show: that a cancel ran, its release stored and its end not recorded, crediting the subconscious's own cancel or another's by its reason, and then whether its own, asked for, had not run, with its note; that its note was delivered; that the cancel it asked for, its own `cancel_tuneout` of that hold answered as waiting, was lost, quoting the first line of its note; or, where nothing shows, that a cancel it asked for then, if any, was lost with any note. A release the boot itself makes (an end time passed, a wake budget spent) isn't read as that run's. A release that already told the note's loss, or a loss the stop kept in the store, gets nothing more; a bare channel id two servers' holds answer to names neither, and the waiting answer names the server (`serverId`); a later boot tells a hold again where it finds more, or an ask made after it was told, and asks the subconscious's turn once. The notice is kept and tried again while the store still refuses, and is traced as `tune-out:stop-unrecorded` (`found`: `ran`, `delivered`, `asked` or `unknown`).
- With the tool-result guard on for the persistent subconscious, where a crash before the guard settled its batch leaves the guard's placeholder for the `cancel_tuneout` result, the boot reads the original result from the guard's audit (`framework/tool-result-guard`, the subconscious's staged batch, by tool use id) where the result row isn't an answer, the row's own answer first where the batch settled, so it finds the waiting answer and doesn't tell the hold conditionally. A staged record whose blob is missing or can't be read as JSON is logged, naming the agent and the blob, and read as absent.
- A release records who asked for its cancel (`cancel.by`), and a boot's notice of an unrecorded stop reads only the persistent subconscious's own name, or none, as its own cancel, so a reader fork's cancel that ran isn't credited to the subconscious. A notice written late, its writes held, doesn't silence an ask made after its boot decided it (it carries `keptAtSequence`), and a notice a boot keeps while writes are held is kept in the loss-notice record at once, so a crash before the writes land leaves it for the next boot.
- A waiting cancel keeps every caller it answered as waiting, and its release records them (`cancel.askers`, `by` the first), so a call of the subconscious's that joined another's waiting cancel (a reader fork's, say) reads as its own cancel when that cancel ran and its end went unrecorded, the others named with it: "The cancel of it you asked for ran (with reader-fork-7's): …".
- A boot writes its run's stamp only once the notices it tells of the last stop's are written to the subconscious or kept in the store, and while one is neither, the stamp still bounds the next boot's reading at the last run's start, so a crash or a refused record between the two leaves the next boot reading that run's rows for the hold. A stop meanwhile (a trace listener's, of a notice's write) keeps its own stamp: no marker of the run is written over it. So does a branch move meanwhile (a failed surgery's restore to the branch it was on), and a boot whose telling of the last stop's stamp throws partway keeps that bound for the run, so the next boot tells the holds it didn't reach from the rows they had.
- The stamp names the branch its run's start is on (`branch`), and a branch move writes this run's stamp on the branch moved to, from that branch's head (or where this run began on it, for one it was on before): a cancel waiting there and lost to a crash is told though that branch's own stamp covered the hold, and an earlier run's rows there aren't read as this run's. A stamp whose start is on another branch than the boot's bounds nothing: each hold it doesn't cover is told conditionally. After a move, the loss record written there first reads in the notices that branch kept, so it doesn't write over them; where this run keeps any, it is written at the move, before the stamp, and the last stop's bound stays where that branch's record can't keep them.
- A boot's notice of an unrecorded stop gives no second row where the boot before wrote the same one from the store's record on a quiesced boot, its window not holding it yet, or where the release it tells of was the last row that boot read: a notice silences what was stored up to the head it was decided at, that head included. The told rows are read from the subconscious's stored rows too.
- A stop's kept notice that the next boot wrote, that boot then dying before its marker, accounts for its hold at the boot after: its row names the bound of the stop's stamp (`lostAtStop`), so the boot after gives no second, conditional report for the same lost cancel.
- Where a boot can't read that run's rows (the read throws, or the stamp's run start is on another branch), its notice says that whether the cancel asked for, or one asked for then, ran isn't known here, that its end was not recorded, and that the note may be lost; a later boot that can read them tells what they show.
- The loss-notice record and each stamp, the stop's and each run's, are made durable as they are written (the store's sync), the record before the stop's stamp that counts on it, so a crash before the store's periodic sync doesn't find an older record or stamp. A record that can't be made durable counts as not kept, so the stop's stamp leaves its holds out.
- A boot after a crash counts a note, or a release telling a queued note's loss, as the subconscious's newest ask of that hold's only where stored after that ask, as a release that ran does: after an earlier cancel's run that stored them and failed before recording the end, then a new ask with another note, the earlier run's note or release isn't read as the later ask's, whose note was lost with its cancel.
- A start makes its first read of the all-except hold's record before anything else, and a throw there refuses the start, as a later read's throw does, so every hold on record is checked against the last stop's stamp before a start writes its own over it, and a later start can still read the last run's rows for a cancel then waiting.
- On a move to a branch made from this run's past its start, as a suppression's fork at the head is, the stamp there keeps this run's start where the host says what a branch was made from (`branchOrigin`), so a boot after a crash can read what this run had asked before the fork (a waiting cancel and its note, which the branch holds); any other branch moved to is read from its head.
