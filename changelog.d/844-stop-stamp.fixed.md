- A reader's note waiting with a tune-out cancel is no longer lost untold when the host crashes, or stops while the store refuses the notice of its loss: each stop now stamps the holds it leaves on record whose waiting cancels it accounted for (`tune-out/<primary>/stop-stamp`), and each boot stamps its own run as covering none, trying again until the store takes it, the subconscious's waiting `cancel_tuneout` answer saying meanwhile that a stop or a death while the store still refuses may go untold. A store with no stamp at all, as one an earlier version wrote or one that refused every stamp, counts as stopped cleanly. For a hold on record the stamp doesn't cover, the boot reads that run's rows up to its own start, the residents' and the subconscious's own (its stored rows where its window isn't presented), and tells the persistent subconscious what they show: that a cancel ran, its release stored and its end not recorded, crediting the subconscious's own cancel or another's by its reason, and then whether its own, asked for, had not run, with its note; that its note was delivered; that the cancel it asked for, its own `cancel_tuneout` of that hold answered as waiting, was lost, quoting the first line of its note; or, where nothing shows, that a cancel it asked for then, if any, was lost with any note. A release the boot itself makes (an end time passed, a wake budget spent) isn't read as that run's. A release that already told the note's loss, or a loss the stop kept in the store, gets nothing more; a bare channel id two servers' holds answer to names neither, and the waiting answer now names the server (`serverId`); a later boot tells a hold again where it finds more, or an ask made after it was told, and asks the subconscious's turn once. The notice is kept and tried again while the store still refuses, and is traced as `tune-out:stop-unrecorded` (`found`: `ran`, `delivered`, `asked` or `unknown`).
- With the tool-result guard on for the persistent subconscious, a crash before the guard settled its batch left the guard's placeholder for the `cancel_tuneout` result, so the boot found no waiting answer and told the hold conditionally. It now reads the original result from the guard's audit (`framework/tool-result-guard`, the subconscious's staged batch, by tool use id) where the result row isn't an answer, the row's own answer first where the batch settled. A staged record whose blob is missing or can't be read as JSON is logged, naming the agent and the blob, and read as absent.
- A boot's notice of an unrecorded stop credited a reader fork's cancel that ran as the subconscious's own: a release now records who asked for its cancel (`cancel.by`), and only the persistent subconscious's own name, or none, reads as its own. A notice written late, its writes held, no longer silences an ask made after its boot decided it (it carries `keptAtSequence`), and a notice a boot keeps while writes are held is kept in the loss-notice record at once, so a crash before the writes land leaves it for the next boot.
- A call of the subconscious's that joined another's waiting cancel (a reader fork's, say) was told, when that cancel ran and its end went unrecorded, that its own cancel had not run. A waiting cancel now keeps every caller it answered as waiting, its release records them (`cancel.askers`, `by` the first), and the subconscious's name among them reads as its own cancel, the others named with it: "The cancel of it you asked for ran (with reader-fork-7's): …".
- A boot now writes its run's stamp only once the notices it tells of the last stop's are written to the subconscious or kept in the store, and while one is neither, the stamp still bounds the next boot's reading at the last run's start: written first, a crash or a refused record between the two left the next boot telling the hold conditionally, where that run's rows said more. A stop meanwhile (a trace listener's, of a notice's write) keeps its own stamp: no marker of the run is written over it.
- The stamp names the branch its run's start is on (`branch`), and a branch move writes this run's stamp on the branch moved to, from that branch's head (or where this run began on it, for one it was on before): a cancel waiting there and lost to a crash is told though that branch's own stamp covered the hold, and an earlier run's rows there aren't read as this run's. A stamp whose start is on another branch than the boot's bounds nothing: each hold it doesn't cover is told conditionally. After a move, the loss record written there first reads in the notices that branch kept, which it wrote over.
