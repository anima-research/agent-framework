- A call whose report names a stored reply's signed thinking the provider dropped now tells the context manager which replies they were, through its `noteThinkingDropped`, with the compile the stream was built from. The context manager then sends those replies without their thinking from the next compile on, so the provider drops none of them again and the calibration takes its sample. Before, with `thinkingBinding.dropBlock`, a reply stored before its branch's thinking-binding record began kept being sent and dropped, with no calibration sample, until a change to what the request sends ahead of it. A context manager without `noteThinkingDropped` is told nothing.
