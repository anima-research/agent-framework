- **The gate's refusals and file errors say what didn't happen, name each field as its caller wrote it, and say what to do.**
  - **`wake_add_rule` names the parameters the agent sent:** a refusal of a `debounceMs`, `rateLimit`, `passiveSample` or `judge` names it so, and its fields as, for example, `rateLimit.tokens`, where it named gate.json's `behavior.debounce`, `behavior.rate_limit.tokens` and `behavior.passive_sample`. A behavior given as an object, in gate.json's form, is named as written there. Its refusals open `Rule "x" wasn't saved`, where they opened `Policy "x"`, and gate_status's notes and the gate's log lines call a rule a rule too.
  - **A placement that names no rule:** `Rule "x" wasn't saved: insertBefore is "y", and no rule has that name.`, with the other rules and the way on, replacing `addPolicy: no policy named "y" to anchor on — have: [...]`.
  - **`passthrough` on a behavior that can't use it** names that behavior as given and says to leave `passthrough` out, replacing `passthrough is only valid with rate_limit or passive_sample behaviors — for "debounce:60000" …`. **A regular expression the gate can't read** says to fix it, or to give `match.filter.type` `"text"`.
  - **`wake_add_rule`'s own refusals** of no behavior, more than one behavior and more than one placement say nothing was saved, and `wake_remove_rule`'s refusal of a missing `name` says nothing was removed.
  - **A gate.json that can't be read or isn't JSON:** gate_status's error opens `gate.json, at <path>, isn't JSON: "<the parse error>"` (or `can't be read:`), says what the gate runs meanwhile as before, and ends with what to do. It opened with the bare parse or filesystem error.
  - **The privileged-users file:** a file that can't be read, isn't JSON, is empty or holds no list gets an error naming the file's path, who is privileged meanwhile (the ids of the list that last loaded, or no one), and that writing `[]` to it or removing it makes no one privileged. An empty file is named as a save in progress. Each of these read `Failed to load privileged-users file: …`. The error naming entries that aren't user ids names the path too.
  - **Text from gate.json or the privileged-users file** that a refusal, gate_status or a `[gate]` log line quotes, such as a parse error's excerpt, a rule's or a field's name, or a value, is quoted with the escaping the framework gives supplied text (`quotedValue`). So a UTF-16 file's NULs reach the agent and the log as `\u0000`, where they came through raw. An error from reading or parsing either file is now quoted, in double quotes, in these texts and in the `gate:config-error` trace's `error`.
